# Goal E：串行集成与固定回归

在 Goals A-D 合并后执行。你负责把四个局部结果串成一个可验收的最小 RepairSlice。

## 工作范围

- 先阅读 A-D 的变更和测试结果，再选择一个固定 BugBoard 场景。
- 只在需要时修改集成测试、固定 fixture、协议适配和本指南；不要重写 A-D 的核心实现。
- 验证 CLI、Web/console 和 Python Agent 对同一个 Run/Event 协议的状态理解一致。
- 记录 Fake 本地闭环、真实外部链路和未完成门禁，不能用 Fake 通过替代真实验收。

## 验收序列

1. `prepare` 冻结项目、版本和 TestSpec。
2. `reproduce` 留存失败证据。
3. `patch` 只修改授权路径并保留 before/after hash。
4. `verify` 重新读取 artifact 并运行 typed gate。
5. `report` 生成报告；失败、取消、未知副作用和恢复均有明确终态。
6. 同一 `run_id` 重试、恢复和重复回执不产生重复副作用。

## 约束

- 不运行完整基线超过一次。
- 不删除、重置或覆盖既有工作区文件；不要把历史测试结果冒充本轮结果。
- 真实 Docker、MCP、Postgres 或模型不可用时，标记为未验证/阻塞并保留 Fake 证据。

## 交付

最终回复必须列出：固定场景、端到端命令、通过/失败/阻塞分层结果、证据路径、剩余风险和下一步。若发现跨模块契约冲突，先停止合并并报告冲突。
