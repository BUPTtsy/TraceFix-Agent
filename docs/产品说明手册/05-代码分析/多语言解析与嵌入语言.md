# 多语言解析与嵌入语言 📐

本文说明解析层（L1）和结构层（L2）如何做到与语言无关。框架相关的语义见 `前端框架适配.md`，工程配置见 `前端工程化适配.md`。

## 2. 语言识别

按以下顺序判断，前面的优先：

1. Profile 显式覆盖（`code_intel.languages`）。
2. `.gitattributes` 中的 `linguist-language`、`linguist-generated`、`linguist-vendored`。
3. 宿主文件的声明：
   - SFC 块的 `lang` 属性，如 `<script lang="ts">`、`<style lang="scss">`、`<template lang="pug">`；
   - HTML `<script type>`，如 `module`、`importmap`、`application/json`、`application/ld+json`、`text/x-template`。
4. 扩展名映射表（第 1 节）。
5. 内容特征：shebang（如 `#!/usr/bin/env node`）。`.js` 文件中出现 JSX 时按 JSX 方言解析。
6. 仍无法识别的文件，或解析后出现大量 ERROR 节点的文件（如带 Flow 类型注解的 JS），标记为 `dialect_unknown`，降为 L0，并发出 degraded 事件。

## 3. 嵌入语言

前端代码大量「一个文件里有多种语言」。解析层按宿主递归拆出子语言。

| 宿主 | 嵌入位置 | 子语言 |
|---|---|---|
| HTML | `<script>`（按 `type`） | JS / TS / JSON / importmap |
| HTML | `<style>` | CSS |
| HTML | `on*="…"` 属性 | JS 语句 |
| HTML | `style="…"` 属性 | CSS 声明 |
| HTML | `<script type="text/x-template">` | Vue 模板 |
| Vue SFC | `<template lang>` | Vue 模板 / Pug |
| Vue SFC | `<script lang setup>` | JS / TS |
| Vue SFC | `<style lang scoped module>` | CSS / SCSS / Less |
| Vue SFC | `<i18n lang>` | JSON / YAML |
| Vue SFC | 模板中的指令值与 `{{ }}` 插值 | JS 表达式 |
| Svelte | `<script lang>`、`<style>` | JS / TS、CSS |
| Svelte | `{…}` 表达式，`on:` / `bind:` 的值 | JS 表达式 |
| Angular | `` @Component({ template: `…`, styles: [`…`] }) `` | Angular 模板 / CSS |
| Angular | 外部 `templateUrl` / `styleUrls` | 不是嵌入，记为 `template_of` 关联 |
| Astro | `---` frontmatter | TS |
| Astro | markup 中的 `{}` 表达式、`<script>`、`<style>` | JS、CSS |
| JS / TS 标签模板 | `` html`…` ``（Lit） | HTML，含 `@click` / `.prop` / `?attr` 绑定 |
| JS / TS 标签模板 | `` css`…` ``、`` styled.x`…` ``、`` keyframes`…` ``（styled-components、emotion、Lit） | CSS |
| JS / TS 标签模板 | `` gql`…` `` / `` graphql`…` `` | GraphQL |
| JS / TS 模板字符串 | 带 `/* html */`、`/* css */` 注释提示 | 按注释指定的语言 |
| MDX | 正文中的 JSX 与 import / export | JSX |
| Markdown | 代码块 | 只做到 L1，用于文档站场景 |

**坐标映射**：

- 每个嵌入片段生成一个虚拟文档：`{host_file, host_range, lang, text, offset_map}`。
- 模板字符串中的 `${}` 插值用占位符替换，保证子语言能被解析；同时记录每个占位符对应的宿主表达式。
- UCM 中的位置、注入条目、工具输出、补丁锚点一律使用**宿主文件坐标**；虚拟文档只在内部使用。
- 外部工具可以直接在虚拟文档上运行，例如 Semgrep、ESLint 处理器（processor）、Stylelint 的 `customSyntax`。结果经 `offset_map` 映射回宿主坐标。
- 可以多层嵌套，例如 HTML → `<script>` → `` html`…` `` → `<style>`，逐层递归处理；同一片段按内容哈希缓存。

## 4. 统一代码模型（UCM）

| 表 | 主要字段 | 说明 |
|---|---|---|
| `files` | path、lang、dialect、hash、level、generated、package、framework | 每个文件一行，记录达到的能力等级 |
| `fragments` | host_path、host_range、lang、hash、offset_map | 嵌入语言片段 |
| `symbols` | id、file、kind、name、qualified_name、range、exported、signature | kind 包括 function、class、component、hook、composable、store、action、variable、type、style_rule、css_var、route、i18n_key、custom_element、graphql_op |
| `refs` | from、to、kind、range、resolved_by | to 可以是符号，也可以是尚未解析的名称。kind 包括 import、call、render、extends、bind_event、bind_prop、emit、prop_callback、dom_query、style_apply、i18n_use、request、route_to、template_of、define_element。resolved_by 取值为 lsp / static / heuristic |
| `elements` | id、file、range、tag、component、role_hint、name_sources、text_parts、attrs、events、condition、loop、parent | 模板中的一个元素。HTML、JSX、Vue、Svelte、Angular、Lit 的元素都归一化到这一张表 |
| `routes` | pattern、method、kind、handler、framework、source | kind 为 page（前端页面）或 api（服务端接口）；source 为 file（约定式）、config（配置式）或 code（手写） |
| `requests` | symbol、method、url_template、client、base、range | fetch、axios、ofetch、HttpClient、GraphQL、tRPC 等调用点 |
| `texts` | key、locale、value、file、range | i18n 文案，支持从值反查键 |
| `styles` | rule、selector、specificity、file、range、scope | scope 为 global、scoped、module 或 shadow |
| `diagnostics_baseline` | tool、file、code、message、range | 补丁前的诊断基线，用于增量比较 |

- 定位与工具只写针对 UCM 的查询，例如 `ui_map(locator)`、`callers(fn)`、`route_of(url)`、`requests_to(route)`、`styles_for(element)`、`text_sources(text)`。
- 各框架写法的归一化规则见 `前端框架适配.md` 第 3 节。

## 5. 声明式适配器

```yaml
# code_intel/adapters/vue/adapter.yaml（示意）
id: vue
version: 1.0.0
detect: {files: ["**/*.vue"], deps: ["vue", "nuxt"]}
languages:
  - {lang: vue, grammar: vue, extensions: [".vue"]}
queries:                                   # tree-sitter 查询，产出 UCM 事实
  injections: queries/vue/injections.scm   # 拆分 template / script / style / i18n 块
  elements:   queries/vue/elements.scm     # 元素、静态文本、插值
  events:     queries/vue/events.scm       # @click、v-on:click、v-model
  symbols:    queries/vue/symbols.scm      # defineProps / defineEmits / defineModel
hooks: vue_hooks                           # 查询表达不了的语义，由内置代码实现
lsp: {server: vue, prefer_workspace_bin: true}
checks: [{id: vue-tsc, via: profile.typecheck}]
fixtures: evals/fixtures/vue3-vite-pinia-i18n
```

`hooks` 用来处理查询表达不了的语义，例如 `<script setup>` 中哪些绑定对模板可见。

**规则**：

- **查询与钩子**：查询文件是数据，可以审计，也可以按项目追加（例如公司内部组件库的元素查询）。钩子是代码，只能使用随 TraceFix 发布、经过评审的内置实现；**不执行仓库提供的代码**。
- **版本记录**：适配器和语法的版本写入注入条目的 `source` 字段（如 `adapter:vue@1.0.0 grammar:vue@x.y`），并进入 Run 报告。
- **可叠加**：同一个 `.vue` 文件会同时经过多个适配器，例如 vue（模板）、typescript（脚本）、scss（样式）、vue-i18n（`<i18n>` 块）。

**新增一种语言的步骤**：

1. 接入语法，并预编译进工具镜像。
2. 复用或编写查询文件。
3. 加入夹具和定位用例。
4. 跑评测，确认已有语言的指标不回退。

## 6. 索引范围与排除

- **默认索引**：Git 跟踪的文件，以及未跟踪但没有被 `.gitignore` 忽略的文件。
- **默认排除**（Profile 可覆盖）：
  - `node_modules`；
  - 构建产物：`dist`、`build`、`out`、`.next`、`.nuxt`、`.output`、`.svelte-kit`、`.angular`、`coverage`；
  - lockfile；
  - 压缩产物：`*.min.js`、`*.min.css`，以及单行极长的文件；
  - 带 `@generated` 标记或 `linguist-generated` 属性的文件。
- **读取但不索引**：自动导入生成的声明文件（如 `components.d.ts`、`.nuxt/components.d.ts`），只用于解析组件名，见 `前端工程化适配.md` 第 5 节。
- **第三方代码**：`node_modules` 不进入 UCM，但 LSP 照常读取其中的类型声明；需要时模型可以用 `code.read` 只读查看。组件库的角色映射见 `前端框架适配.md` 第 4 节。
- **敏感文件**：`.env*`、私钥、证书等不索引、不注入，与推送前的 secret scanning 使用同一套规则。
- 不设文件数量或体积上限。

## 7. 增量与缓存

- **缓存键**：文件内容哈希 + 语法版本 + 适配器版本。
- **PREPARE 阶段**：全量构建，与基线测试并行；同一仓库、同一 commit 的索引可以跨 Run 复用。
- **补丁应用后**：
  - 只重新解析变更的文件及其嵌入片段；
  - 受影响的跨文件事实（导入方、事件链、样式作用对象）标记为 stale 并重算；
  - StructuredEdit 之后用 tree-sitter 的增量解析（`tree.edit`）快速重解析。
- **隔离**：解析在独立的 worker 进程中执行，单个文件受单次操作超时保护。超时或崩溃的文件降为 L0，并记录原因。
