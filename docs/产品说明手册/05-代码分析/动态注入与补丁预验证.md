# 动态注入与补丁预验证 📐

本文说明代码情报的结果如何进入模型上下文（推送式注入 + 按需工具），以及补丁在进入 GUI 验证之前如何做按语言的预验证。

## 1. 事件驱动的注入

上下文注入器（Context Injector）订阅引擎事件，把分析结果写入上下文区块 `code_insights`：

| 触发事件 | 分析 | 注入内容 | 阶段 |
|---|---|---|---|
| 观测中出现 console error 或 pageerror | 堆栈映射 | 出错帧的 `file:line`、上下各 10 行、所属函数或组件的签名 | EXPLORE / DIAGNOSE |
| 出现框架警告（Vue warn、React 水合不匹配、Angular `NG0xxx`） | 框架栈解析 | 组件链和相关绑定 | EXPLORE / DIAGNOSE |
| 网络 4xx / 5xx，或 GraphQL 返回 errors | 网络映射 | 客户端调用点和服务端处理器摘要 | EXPLORE / DIAGNOSE |
| 看图工具返回带 bbox 的发现 | 探针取元素，然后定位 | 元素候选和样式来源 | EXPLORE / DIAGNOSE |
| 断言失败（进入 REPRODUCE / DIAGNOSE） | GUI → 代码定位 | UiCodeMap 排名前 3 的候选 | DIAGNOSE |
| 定位回放完成 | 插桩位置、样式来源 | 更新后的 UiCodeMap | DIAGNOSE |
| 进入 DIAGNOSE | 可疑度排序（第 3 节） | 排名靠前的符号卡片：签名 + 关键片段，不给整个文件 | DIAGNOSE |
| 命中静态规则 | Semgrep / tree-sitter query | Finding 位置 + 规则说明 | DIAGNOSE |
| 生成 PatchProposal 之后 | 预验证（第 6 节）、变更符号的引用方 | 预验证失败时作为反馈返回；通过时附上影响范围 | PATCH |
| VERIFY 失败 | 失败输出与变更符号关联 | 「哪个修改可能导致了失败」 | DIAGNOSE |

## 2. 注入条目与规则

```json
{"id": "ci_7f3a",
 "kind": "ui_map|stack|network|style|symbol|static_finding|patch_precheck|impact",
 "source": "adapter:vue@1.0.0 grammar:vue@x.y lsp:vue-language-server@x.y",
 "lang": "vue", "framework": "vue@3", "level": "L2", "confidence": 0.82,
 "location": "src/components/TaskItem.vue:3-5", "content": "...", "tokens": 312, "artifact_ref": "..."}
```

- **窗口占比**：`code_insights` 默认最多占模型上下文窗口的 25%。这是单次请求内的空间分配，不是预算。条目按「置信度 × 与当前失败的相关度」排序后截断；被截掉的条目只保留 id 和位置，模型可以用 `code.read` 或 `code.ui_map` 取回。
- **去重**：同一位置只保留最新、最完整的一条。
- **失效**：补丁应用后，受影响文件及其跨文件关联（导入方、事件链、样式作用对象）的条目标记为 stale，下次注入前重新计算。
- **引用**：模型的 `PatchProposal` 新增 `insight_refs` 字段，用于轨迹归因，即记录哪些分析结果真正帮到了修复。
- **等级可见**：条目带 `level`。L0 / L1 条目在提示中标注「近似结果」，避免模型过度信任。

## 3. 可疑度排序（Fault Localization）

对每个候选符号或元素计算综合得分：

```text
score = 0.30·UI 映射置信度          + 0.20·是否出现在错误堆栈
      + 0.10·与失败请求的关联        + 0.10·与失败断言的数据流距离（取反比）
      + 0.10·是否在当前路由的渲染子树内 + 0.08·近期是否变更（git log，需要发布检出）
      + 0.07·是否命中静态规则        + 0.05·检索相关度（现有 RRF）
```

- 权重初始值由人工设定，之后用 `evals/` 中标注的真实修复位置做离线校准（网格搜索，不涉及模型训练）。
- 缺失的信号按 0 计，不影响其他信号。

## 4. 按需拉取的工具

除了推送式注入，DIAGNOSE 阶段还向模型暴露一组只读工具，可以并行调用。工具注册方式见 `03-Agent运行时/工具调用与Skill.md`；代码情报类工具的完整清单以本表为准。

| 工具 | 说明 |
|---|---|
| `code.symbols(path)` | 文件中的符号，包括 SFC 的各个块 |
| `code.definition(symbol)`、`code.references(symbol)` | L3 时走 LSP；否则按名称近似匹配，并在结果中标注 |
| `code.callers(fn, depth)` | 调用方；`depth` 默认 2，模型可以指定更深 |
| `code.ui_map(locator, page?)` | UiCodeMap，支持翻页 |
| `code.element(loc)` | 模板元素的属性、绑定和事件链 |
| `code.events(element \| component)` | 跨组件事件链：emit、回调 prop、`@Output` |
| `code.route(url)` | 页面 URL → 页面组件和渲染子树；接口 URL → 处理函数 |
| `code.requests(url \| method)` | 客户端调用点和服务端处理器 |
| `code.styles(element \| selector)` | 命中的 CSS 规则及其来源 |
| `code.i18n(text \| key)` | 文案、键和使用点之间的互查 |
| `code.search(query, glob)`、`code.read(path, start, end)` | 文本层工具，任何文件都可以用 |

## 5. StructuredEdit：多锚点补丁

```json
{"path": "src/components/TaskItem.vue", "before_hash": "sha256:…",
 "anchor": {"element": "src/components/TaskItem.vue:3:5", "attr": "@change"},
 "search": "emit('toggle', task.id)", "replace": "emit('toggle', task.id, !task.done)"}
```

| 锚点 | 适用 | 示例 |
|---|---|---|
| `symbol` | 函数、类、组件、组合式函数、store action | `{"symbol": "toggleTask"}` |
| `element`，可附 `attr` | 任意框架的模板元素；附 `attr` 时只修改某个属性或绑定 | `{"element": "…:3:5", "attr": "class"}` |
| `block` | SFC 的块 | `{"block": "style"}` |
| `style_rule` | CSS 规则，包括 `<style>` 块内的规则 | `{"style_rule": ".task .done"}` |
| `json_path` | JSON / YAML 中的键，如 i18n 文案、配置 | `{"json_path": "$.task.complete"}` |
| `line_range` | 兜底 | `{"line_range": [12, 18]}` |

- **定位与替换**：运行时用 UCM 把锚点解析为宿主文件中的范围，在该范围内执行 search / replace。search 不唯一或找不到时，返回精确的错误信息和候选位置列表。
- **即时语法检查**：替换后立即增量重解析；ERROR / MISSING 节点增加就拒绝，并把原因反馈给模型。
- **嵌入语言**：锚点和范围都使用宿主文件坐标（见 `多语言解析与嵌入语言.md` 第 3 节）。
- **i18n**：修改某个键时，提示其他语言文件中同一键的状态（缺失或未同步），由模型决定是否一并修改。
- **回退方案**：保留完整文件替换，用于新文件和小文件。
- **统一输出**：两种格式最终都生成统一 diff，`patch_hash` 的语义不变（`engine.py:541-543`）。

## 6. 补丁预验证

**原则**：

- **只比较增量**：补丁前的诊断存入 `diagnostics_baseline`。只有补丁新增的问题才算失败，存量问题不阻塞修复。
- **项目配置优先**：优先使用项目自己的脚本和配置（Profile 中已审计的命令）。项目没有相应配置时，使用工具镜像中的工具和默认配置，并且只在增量模式下运行。
- **全部在沙箱内执行**。
- **先快后准**：L3 就绪时，先向 LSP 取变更文件及其依赖方的诊断，快速反馈。LSP 没有新增诊断后，再执行项目的类型检查命令，以它的结果作为预验证的最终结论。

| 语言 / 框架 | 语法检查 | 类型检查 / 编译 | Lint |
|---|---|---|---|
| 所有有语法的语言 | ERROR / MISSING 节点不增加（总是执行） | — | — |
| JS / TS / JSX / TSX | 同上 | 项目的 typecheck 脚本，或 `tsc --noEmit --incremental` | ESLint |
| Vue | 同上，包括模板 | `vue-tsc --noEmit` | ESLint + eslint-plugin-vue |
| Svelte | 同上 | `svelte-check` | ESLint + eslint-plugin-svelte |
| Angular | 同上，包括模板 | 项目的构建脚本或 `ngc -p <tsconfig>`；开启 `strictTemplates` 时也检查模板类型 | angular-eslint |
| Astro | 同上 | `astro check` | — |
| CSS / SCSS / Less | 同上 | sass / less 编译 | Stylelint |
| HTML | 同上 | — | html-validate |
| JSON / YAML | 解析 | 已知文件按 JSON Schema 校验，如 `package.json`、`tsconfig.json` | i18n 键一致性：各语言文件的键集合不因补丁出现新的差异 |
| 服务端（Node） | 同上 | 同 JS / TS | 同 JS / TS |

**失败处理**：

- **预验证失败**：把诊断（位置、消息、与补丁的关系）反馈给模型，退回 DIAGNOSE，不触发 GUI 验证，不设次数上限。
- **反复失败**：同一补丁或同一诊断反复出现时，由死循环检测的「补丁重复」「错误重复」信号处理（开发计划 3.3 节）。
- **工具无法运行**：例如缺依赖或配置错误。这种情况记为该检查项「不可用」，并发出 degraded 事件；不算补丁失败，也不阻塞后续的六类验证。
- **通过也不等于修复成功**：是否修复成功，仍由 VERIFY 的六类验证决定。

## 7. 与现有机制的关系

- **验证门禁**：预验证不属于六类验证，不影响 `verification_gate`；插桩构建的证据也不进入门禁（`GUI到代码定位.md` 7.3 节）。
- **上下文窗口**：`code_insights` 的窗口占比和压缩规则，见 `06-上下文与子Agent/记忆与上下文压缩.md`。
- **检测规则**：static 类规则（Semgrep / tree-sitter query）的编写和管理见 `04-检测规则`。代码情报服务负责执行这些规则，并把命中结果作为注入条目。
- **子 Agent**：code-explorer 子 Agent 调用同一组只读工具，见 `06-上下文与子Agent/子Agent派发.md`。
