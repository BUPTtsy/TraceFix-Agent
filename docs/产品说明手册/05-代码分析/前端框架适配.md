# 前端框架适配 📐

本文说明框架层（L2）如何把各 UI 框架的组件、模板、事件、状态、样式和 i18n 写法归一化到统一代码模型（UCM，见 `多语言解析与嵌入语言.md` 第 4 节）。元框架、构建工具与路由见 `前端工程化适配.md`。

## 1. 框架探测

探测按包进行，monorepo 中的每个包单独探测。

| 信号 | 示例 |
|---|---|
| 依赖 | `package.json` 的 dependencies / devDependencies：`vue`、`react`、`@angular/core`、`svelte`、`solid-js`、`lit`、`preact`、`jquery` |
| 配置文件 | `vite.config.*` 的插件列表（`@vitejs/plugin-vue`、`@vitejs/plugin-react`、`@sveltejs/vite-plugin-svelte`）；`vue.config.js`；`angular.json`；`nuxt.config.*`；`next.config.*`；`svelte.config.*`；`astro.config.*` |
| 文件特征 | `.vue` / `.svelte` / `.astro` 文件、`@Component(` 装饰器、`customElements.define(` |
| 版本 | 读取 lockfile 中实际安装的版本。Vue 2 与 Vue 3、Svelte 4 与 Svelte 5、React 18 与 React 19 的适配差异都很大 |

- 探测结果写入 `framework_profile`，包括框架及版本、UI 组件库、状态库、路由库、i18n 库，并进入 Run 报告。
- 一个项目可以同时有多个框架，例如 Astro 岛、微前端，或正在从 Vue 2 迁移到 Vue 3 的项目。

## 2. 适配矩阵

### 2.1 组件与模板

| 框架 | 组件定义 | 模板 / 元素来源 | 标签 → 组件解析 |
|---|---|---|---|
| 原生 HTML / jQuery | 无，页面即单元 | HTML 文件、`innerHTML` 与模板字符串、`document.createElement` | 无；JS 通过选择器关联元素（`dom_query`） |
| React / Preact | 返回 JSX 的函数（首字母大写）、class 组件；`memo` / `forwardRef` / HOC 包装 | JSX / TSX | 作用域内的标识符 → import |
| Vue 3 | SFC；`defineComponent`；`<script setup>` | `<template>`、渲染函数、JSX | 见 5.3 节 |
| Vue 2 | SFC；Options API；`Vue.extend`；vue-class-component | `<template>`、渲染函数 | `components` 选项、`Vue.component` 全局注册 |
| Angular | `@Component({selector, template / templateUrl, styles / styleUrls})` | 外部或内联模板 | 按 selector 匹配（元素、属性、class 选择器）；查找范围是 standalone 组件的 `imports` 或 NgModule 的 `declarations` |
| Svelte 4 / 5 | `.svelte` 文件即组件 | markup | import |
| Solid | JSX 函数组件 | JSX | import |
| Lit / Web Components | `class extends LitElement / HTMLElement`、`@customElement` | `` html`…` `` 模板、Shadow DOM | 标签名 → `customElements.define` / `@customElement` 注册 |
| Astro | `.astro` 组件；岛内可以是其他框架的组件 | markup | import |

### 2.2 事件与状态

| 框架 | DOM 事件绑定 | 跨组件事件 | 状态读写 |
|---|---|---|---|
| 原生 / jQuery | `onclick=` 属性、`addEventListener`、`el.onclick =`、`$(sel).on()`；事件委托（`e.target.closest(sel)`） | `dispatchEvent(new CustomEvent())` | 全局变量；DOM 读写（`textContent`、`classList`、`value`）；`localStorage` |
| React / Preact | `onClick={}` | 回调 prop：父组件 `onToggle={handle}`，子组件调用 `props.onToggle()`（`prop_callback`） | `useState` / `useReducer` / `useContext`；Redux、Zustand、Jotai、MobX；TanStack Query、SWR |
| Vue | `@click` / `v-on:click`（含修饰符）、`v-model` | 子组件 `emit('toggle')`，父组件 `@toggle="…"`（`emit`）；`v-model` ↔ `update:modelValue` / `defineModel` | `ref` / `reactive` / `computed` / `watch`；Options API 的 `data` / `methods` / `computed`；Pinia、Vuex |
| Angular | `(click)`、`@HostListener` | `@Output()` / `output()` + 父模板 `(toggled)` | 组件字段、Signals、RxJS Subject、NgRx、注入的服务 |
| Svelte | `on:click`（4）、`onclick`（5） | `createEventDispatcher`（4）、回调 prop（5） | `let` 响应式（4）、runes `$state` / `$derived`（5）、store `$store` |
| Solid | `onClick`、`on:click` | 回调 prop | `createSignal`、`createStore` |
| Lit | `@click=${…}` | `dispatchEvent(new CustomEvent())` | `@property` / `@state` |

### 2.3 样式与 i18n

| 框架 | 样式 | 常见 i18n 库与调用方式 |
|---|---|---|
| 原生 | `<link>`、`<style>`、`style=` | 自定义字典 |
| React | CSS / CSS Modules、styled-components、emotion、Tailwind，以及 UI 库的 `sx` / `style` prop | react-i18next `t()` / `<Trans>`；react-intl `formatMessage` / `<FormattedMessage>` |
| Vue | `<style scoped>`、`<style module>`（`$style.x`）、`:class` / `:style` 绑定、Tailwind、UnoCSS | vue-i18n `$t()` / `t()` / `v-t` / `<i18n>` 块 |
| Angular | 组件样式 + ViewEncapsulation、`[class.x]` / `[ngClass]` | `@angular/localize`（`i18n` 属性、`$localize`）；ngx-translate（`\| translate`） |
| Svelte | `<style>`（默认带作用域）、`class:x` | svelte-i18n `$_()` |
| Lit | `` static styles = css`…` ``（Shadow DOM） | `@lit/localize` `msg()` |

## 3. 写法归一化

不同框架的同一种写法，都写入 `elements` / `refs` 表中的同一种字段，定位逻辑因此与框架无关。

**事件绑定**，统一写为 `events: [{event: "click", handler_expr, handler_symbol}]`：

| 写法 | 框架 |
|---|---|
| `onClick={toggle}` | React / Solid / Preact |
| `@click="toggle"`、`v-on:click="toggle"` | Vue |
| `(click)="toggle()"` | Angular |
| `on:click={toggle}`、`onclick={toggle}` | Svelte 4 / 5 |
| `@click=${this.toggle}` | Lit |
| `onclick="toggle()"` | 原生 HTML |
| `el.addEventListener('click', toggle)`、`$(sel).on('click', toggle)` | 原生 / jQuery；通过 `dom_query` 关联到元素 |

**属性绑定**，统一写为 `attrs["aria-label"] = {kind: literal | template | expr | i18n, …}`：

| 写法 | 框架 |
|---|---|
| `aria-label={…}` | JSX、Svelte |
| `:aria-label="…"` | Vue |
| `[attr.aria-label]="…"` | Angular |
| `aria-label=${…}` | Lit |

展开属性（`{...props}`、`v-bind="obj"`）记为动态属性，相关匹配的置信度下调。

**内容投影**：插槽内容写在父组件文件里，却渲染在子组件内部。这类元素的源码位置在父组件中，定位时两边都要查。对应写法包括：

- React：`children`；
- Vue：`<slot>` 与 `v-slot` / `#name`；
- Angular：`<ng-content>`；
- Svelte：`<slot>`（4）、snippet / `{@render}`（5）；
- Web Components：`<slot>`。

**条件与循环**：`v-if`、`*ngIf` / `@if`、`{#if}`、JSX 的 `&&` 与三元表达式，都写入 `condition`；`v-for`、`@for`、`{#each}`、`.map()` 都写入 `loop`，并记录迭代变量对应的数据源。

## 4. 组件库角色表

UI 组件库的源码在 `node_modules` 中，不进入 UCM。为了把 a11y 角色对应到组件用法，系统内置一份声明式角色表：

```yaml
# code_intel/component_roles/element-plus.yaml（示意）
library: element-plus
match: {tags: ["el-checkbox", "ElCheckbox"], import_from: "element-plus"}
role: checkbox
name_from: [default_slot, label_prop, aria-label]
events: {change: [change, "update:modelValue"]}
```

- **首批（P1）**：Element Plus、Ant Design Vue、Naive UI、Vant、Vuetify、Arco Design、TDesign、Ant Design、MUI、Angular Material、Headless UI。
- **源码在项目内的库**：shadcn/ui 等把组件源码复制进项目的库，直接走源码分析，不需要角色表。
- **标签前缀冲突**：Ant Design Vue 与 Arco Design Vue 都使用 `a-` 前缀，按实际的 import 和依赖区分。
- **没有角色表的组件**：用运行时证据补齐。只读探针拿到组件渲染出的 DOM 以及最近的已插桩祖先元素（见 `GUI到代码定位.md` 第 7 节），据此推断映射，作为角色表候选，人工确认后入库。
- **公司内部组件库**：按同样格式在管理后台维护，与检测规则共用版本与审计机制。

## 5. Vue 适配详解

### 5.1 SFC 与脚本

- **块**：`<template>`、`<script>` 与 `<script setup>`（两者可以并存）、`<style scoped | module>`（可以有多个），以及自定义块（如 `<i18n>`）。每个块按 `lang` 交给对应的语言适配器。
- **`<script setup>`**：
  - 顶层的绑定（变量、函数、import 进来的组件）都对模板可见；
  - 解析 `defineProps`、`defineEmits`、`defineModel`、`defineExpose`、`withDefaults`，包括类型参数写法和运行时对象写法。
- **Options API**：解析 `data()`、`methods`、`computed`、`watch`、`props`、`emits`、`components`、`mixins`；模板中的 `x` 对应 `this.x`。
- **Vue 2 特有写法**：filters（`{{ x | f }}`）、`.sync` 修饰符（等同于 `update:x`）、`$listeners`、`Vue.set`；vue-class-component / vue-property-decorator 中的装饰器组件。Vue 2.7 也支持 `<script setup>`。

### 5.2 模板指令的归一化

| 写法 | 归一化 |
|---|---|
| `@click="toggle"`、`@click.prevent.stop="…"` | 事件绑定；修饰符记入 `modifiers` |
| `@click="toggle(task)"`、`@click="() => emit('x')"` | 保留 `handler_expr`，并从表达式中解析出被调用的函数或 `emit` |
| `:attr="…"` / `v-bind:attr` | 属性绑定 |
| `v-bind="obj"` | 动态展开，置信度下调 |
| `v-model="x"`（原生输入框） | 绑定 `value` / `checked`，并登记 `input` / `change` 事件对 `x` 的写入 |
| `v-model="x"` / `v-model:title="x"`（组件） | prop `modelValue` / `title`，加上事件 `update:modelValue` / `update:title` |
| `v-if` / `v-else-if` / `v-else` / `v-show` | `condition` |
| `v-for="t in tasks"` | `loop`，迭代变量关联到数据源 |
| `v-slot` / `#name="{ item }"` | 内容投影（第 3 节） |
| `v-html` | 内容来自表达式，文本匹配改为在数据中查找 |
| `{{ expr }}` | 文本中的动态槽 |
| `ref="inputEl"` | 模板 ref，关联到脚本中同名的 ref |
| `:class` / `:style`（对象或数组语法） | 样式作用关系（`style_apply`） |
| `v-t="'key'"` | i18n 使用点 |

### 5.3 组件解析

模板中的 `<TaskItem>` 或 `<task-item>`，按以下顺序解析为组件（PascalCase 与 kebab-case 互相等价）：

1. `<script setup>` 中的 import；
2. `components` 选项中的局部注册；
3. `app.component()` / `Vue.component()` 全局注册；
4. 自动导入：unplugin-vue-components、Nuxt，见 `前端工程化适配.md` 第 5 节；
5. 组件库角色表（第 4 节）。

### 5.4 生态

| 方面 | 支持 |
|---|---|
| 状态 | Pinia：`defineStore` 的 options 写法和 setup 写法、`storeToRefs`、actions 中的写入点。Vuex：`state`、`mutations`、`actions`、`commit` / `dispatch` 字符串到处理函数的映射 |
| 路由 | vue-router 的 `routes` 配置、`<RouterLink :to>`、`router.push()` |
| i18n | vue-i18n：`$t`、`useI18n().t`、`v-t`、`<i18n>` 块、全局 locale 文件 |
| 类型与 LSP | @vue/language-server（Volar）、`vue-tsc` |
| 构建 | Vite + `@vitejs/plugin-vue`、Vue CLI（webpack + vue-loader）、Nuxt |
| 组件库 | Element Plus、Ant Design Vue、Naive UI、Vant、Vuetify、Arco Design Vue、TDesign Vue |

### 5.5 完整示例

项目结构（示意）：

```text
src/views/Board.vue           # 路由 /board 对应的页面
src/components/TaskList.vue   # <TaskItem v-for="task in store.tasks" :task="task" @toggle="store.toggleTask" />
src/components/TaskItem.vue   # 见下
src/stores/tasks.ts           # Pinia：toggleTask(id) → api.updateTask(id, {done})
src/api/tasks.ts              # updateTask → PATCH /api/tasks/:id
src/locales/zh-CN.json        # {"task": {"complete": "完成 {title}"}}
server/routes/tasks.ts        # router.patch('/api/tasks/:id', …)
```

`TaskItem.vue`：

```vue
<template>
  <li class="task">
    <input type="checkbox" :checked="task.done"
           :aria-label="t('task.complete', { title: task.title })"
           @change="emit('toggle', task.id)" />
    <span :class="{ done: task.done }">{{ task.title }}</span>
  </li>
</template>
<script setup lang="ts">
const props = defineProps<{ task: Task }>()
const emit = defineEmits<{ toggle: [id: string] }>()
const { t } = useI18n()
</script>
```

在 `/board` 页面上，定位失败断言中的元素 `checkbox "完成 撰写项目简介"`：

1. **路由收窄**：`/board` → `Board.vue`，其渲染子树包含 `TaskList.vue` → `TaskItem.vue`。
2. **角色**：`checkbox` 对应 `<input type="checkbox">` 的隐式角色。
3. **名称**：在 `zh-CN.json` 中反查到 `task.complete = "完成 {title}"`，其中静态部分「完成 」匹配，`{title}` 是动态槽。使用点是 `TaskItem.vue:4` 的 `:aria-label`。
4. **事件链**：`@change` → `emit('toggle', task.id)` → 父组件 `TaskList.vue` 中的 `@toggle="store.toggleTask"` → Pinia 的 `toggleTask` → `api.updateTask` → `PATCH /api/tasks/:id` → 服务端处理函数。
5. **数据来源**：动态槽的值「撰写项目简介」出现在观测到的 `GET /api/tasks` 响应中，说明这段文案来自接口数据，而不是静态文本。

输出的 UiCodeMap 见 `GUI到代码定位.md` 第 10 节。

## 6. 运行时辅助信号（开发模式，可选）

| 框架 | 信号 | 可靠性 |
|---|---|---|
| React 19 | 组件栈；owner stack（19.1 起的 `captureOwnerStack`，仅开发模式） | Fiber 上的 `_debugSource` 已在 React 19 移除，不能依赖 |
| Vue 3 | 开发模式下，DOM 元素可以回溯到所属的组件实例；`@vitejs/plugin-vue` 在开发模式下为组件定义注入 `__file` | 内部字段，随版本变化，接入时核实 |
| Angular | 开发模式下的全局调试 API：`ng.getComponent`、`ng.getOwningComponent` | 官方调试 API，仅开发模式 |
| Svelte | 开发模式下元素上的 `__svelte_meta`，其中包含源码位置 | 内部字段，接入时核实 |

这些信号只作为辅助。主路径是 TraceFix 自己的编译期插桩（`data-tf-loc`），见 `GUI到代码定位.md` 7.2 节。

## 7. 新增框架的步骤

1. 编写探测规则（依赖、配置文件、文件特征、版本）。
2. 编写元素、事件、属性、条件 / 循环、内容投影、跨组件事件的查询。
3. 实现「标签 → 组件」的解析钩子。
4. 补充状态库、路由库、i18n 库的适配（多数可以复用已有的 JS / TS 查询）。
5. 可选：插桩适配与运行时辅助信号。
6. 加入夹具与定位用例，跑评测。
