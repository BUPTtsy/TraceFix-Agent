# 调用方评审反馈驱动修复

> 定位更新：2026-10-07。PR 采集、确认界面和评论回复由调用方自行处理；TraceFix 接收修订目标与执行信息，继续提供定位、修补和验证能力，不感知或判断调用者及 reviewer 的身份 / 用户权限。规则 / Task / Run 索引 / 文档当前使用 SQLite，仓库配置仍包含 YAML / JSON 注册表；SQLite 后续迁移 MySQL。

## 1. 现状与范围

`runtime/guidance.py` 已有 L1 提示、L2 约束、L3 改目标；`runtime/continuation.py` 提供有条件的继续 / 派生能力，拒绝普通续跑 `FIX_VERIFIED` / `NO_BUG_FOUND`。

当前没有专用评审意见整理、远端采集或同 PR 修订流程。平台评审接入是可选接口扩展，不是接口型 Beta 的必交工作；不把现有 Guidance 当成完整评审闭环已交付。

## 2. 平台准备反馈

调用方取得评审内容，提供仓库、当前 PR head / 源码 revision、来源 Run / Finding、评审引用、明确目标和验收规范。调用方决定采纳哪些评论、是否需要澄清以及何时创建 / 启动修订任务；TraceFix 只校验执行信息、来源绑定与执行策略，不判断用户是否有权发起修订。

评审正文属于不可信输入。要求扩大路径、绕过工具策略、删除测试、泄露凭据或放宽业务断言的内容不能成为 Agent 的授权依据；缺少位置或行为预期时应返回需澄清，不能猜测验收目标。

## 3. Agent 接收与执行

| 反馈类型 | 使用边界 |
|---|---|
| L1 提示 | 补充观察或定位线索，不改变原目标 / 规范 |
| L2 约束 | 明确允许路径、改动规模与禁止事项；运行时独立校验 |
| L3 改目标 | 显式确认后派生 Run，重新冻结目标与规范 |
| 已完成修复后的新需求 | 创建 Task，或编辑终态 Task 后单独 start；每次启动新建 Run，绑定当前源码与历史来源，旧成功证据不能替代新验证 |

修订仍经历必要的复现、诊断、最小 patch 和原问题 / 正常业务回归。来源跨仓库、源码过期、补丁 hash 不匹配或验收无法执行时，不输出已验证修复。

TraceFix 返回新 diff、逐项验证和反馈引用；平台把结果对应到评审线程，并决定提交、更新 PR 和回复。

## 4. 可选文本整理能力 📐

如平台需要 Agent 帮助整理评论，可使用独立用途的 system prompt，输出结构化修订草稿：

- 来源评论引用、相关文件 / 行、问题描述和预期行为；
- 建议目标与可执行验收条件；
- 与冻结规范 / 规则冲突的项、需澄清项及拒绝原因；
- 草稿版本与 hash，供平台确认后作为新任务输入。

模型整理不授予工具权限，也不代表评论事实成立；确定性校验必须检查来源、路径和业务约束。该专用接口、提示词与评测仍待实现，不要求建设评审管理后台。

## 5. 验证要求

覆盖未授权来源、恶意评论、过期源码、目标冲突、需澄清和历史证据误复用。真实修订成功需要当前补丁和完整验证；模拟评论或整理草稿不能计作远端交付成功。

主交付计划仍是[接口型 Beta 的 B0–B5](../00-项目进度/接口型Beta最小补足与开发计划.md)。
