# 平台任务输入与运行中干预

> 定位更新：2026-10-07。平台通过任务输入和受限 Guidance 调整 Agent；用户身份、确认界面和跨任务编排由平台承担。

## 1. 任务输入与冻结

平台提交 repo / project、具体源码 revision、受审 Profile、目标、规则与 TestSpec。现有 CLI `--run --goal`、`--spec` 和 Web AgentDock 是调试入口；稳定任务 API 按 B4 补齐，不要求新的任务向导。

`goal`、TestSpec 和复现计划遵守 Run 冻结语义。一次修复的输入范围必须能映射到授权源码与测试环境；任务约束只能收窄权限，不能扩大路径或网络范围。

TaskBrief / PLAN 是可选计划扩展，尚未交付完整契约，不作为 Beta 前置。多个场景的任务分配、排队、用户确认与结果汇总由平台负责；不把 PR 发布策略和用户账户配置放入 Agent 任务输入。

## 2. 已有分级 Guidance

`runtime/guidance.py`、Engine 及现有 CLI / Web 引导入口已接入持久化队列、受保护上下文和逐条 ack；早期“notes 只记录、Web 无干预”的描述已不适用。

| 级别 | 用途 | 处理边界 |
|---|---|---|
| L0 控制 | 暂停 / 继续 / 取消 | 使用已有运行控制与支持的状态，安全边界生效 |
| L1 hint | 补充定位线索和观察 | 下一次模型调用注入 `user_guidance`，记录实际使用和 ack |
| L2 constraint | 限制路径、文件数 / 行数、禁止事项 | 确定性门禁收窄补丁与工具范围，不扩大 Profile 权限 |
| L3 retarget | 修改目标 | 显式确认后结束 / 替代父 Run，派生新 Run 并重新冻结规范 |

实际允许状态、字段和事件以源码为准；稳定外部 Guidance API 的路径和版本需在接入时明确，不能把规划中的 `/api/v1/runs/{id}/guidance` 当成当前接口承诺。

## 3. 来源与执行约束

- 记录 Guidance ID、Run、级别、文本、来源引用、状态与 ack；平台主体标识用于追溯，不要求 TraceFix 建立用户表。
- `user_guidance` 是受保护上下文；引导的注入、采纳或拒绝写入运行事件。
- 引导优先于网页 / 知识内容，但不能覆盖系统策略、冻结规范、规则或工具授权；被拒绝的请求保留原因。
- L3 派生保留父子 Run 与证据来源；继承证据只作输入，新目标仍需独立验证。
- 成功 Run 的新需求不直接普通续跑；使用新建 / 派生任务，核对当前源码与 patch hash。
- 用户输入不能解除 UNKNOWN 核查要求或允许盲重放，暂停 / resume 也不承诺任意浏览器状态恢复。

## 4. 平台反馈与验收

平台可将评审、QA 反馈或人工观察转换为新任务 / Guidance，先完成调用授权并明确来源、目标与可执行验收。PR 采集、评论整理确认和回复由平台处理；可选专用整理能力见[平台评审反馈](PR评审意见驱动修复.md)。

验证 L1 的实际上下文与 ack、L2 越界拒绝、L3 显式确认 / 派生 / 重新验证及跨 Run 拒绝；不能用“收到请求”代替“已生效”。真实长任务效果继续单独评测，接口型 Beta 工作包见[计划](../00-项目进度/接口型Beta最小补足与开发计划.md)。
