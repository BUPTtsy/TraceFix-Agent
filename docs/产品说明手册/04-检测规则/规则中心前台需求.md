# 规则中心调试页面

本文记录现有规则页面的交互与实现，用于研发调试和演示。规则编辑、用户权限及发布流程由上层 GUI 平台负责；页面产品化不作为 Agent 接口组件的交付目标。

## 1. 页面与入口

- 入口：BugBoard 左侧「检测规则」，路由为 `#rules`；页面沿用当前项目选择器，不允许跨项目误编辑。
- 页面区块：规则列表、规则编辑器、版本与质量。规则中心不复用知识库编辑器，避免把非可信经验误当成确定性规则。
- 当前项目为空时，列表只展示空状态，禁止新建规则；切换项目后重新加载规则和质量指标。

## 2. 列表需求

| 需求 | 行为 |
|---|---|
| 搜索 | 匹配规则 ID、名称、标签；输入变化后刷新列表 |
| 筛选 | 按草稿、已启用、已停用、已归档筛选 |
| 展示 | 名称、类型、类别、严重级别、优先级、版本、命中总数、误报率、状态 |
| 选择 | 点击行打开编辑器；当前编辑行有选中态 |
| 新建 | 创建草稿，默认当前项目作用域、EXPLORE/DIAGNOSE/VERIFY 阶段和 console Oracle 示例 |
| 空状态 | 说明规则会在 Run 启动时冻结，父子 Run 的继承与追加语义 |

## 3. 编辑需求

表单必须校验规则 ID、名称、类型、类别、严重级别和优先级。检测配置与作用域使用 JSON 编辑区；保存由 `backend/packages/console-service` 按共享规则契约校验，Python Agent 读取时使用 Pydantic 校验。控制台数据请求不启动 Python 子进程。

- Oracle：填写 `kind`、locator、console ignore、network 状态码和 URL 模式等配置。
- Static：填写 `regex`/`pattern` 与 `path_globs`；当前适配器返回 path/line Finding。
- Guided：填写引导正文和修复指引，发布后作为受保护 `detection_rules` 注入模型。
- 作用域：填写 `level`、项目/任务/Run ID、URL 模式和路径 glob。运行详情展示父 Run 冻结版本，勾选追加规则后通过派生接口的 `additionalRuleIds` 传递到 Python `additional_rule_ids`，页面不修改父快照；父 Run 没有快照时禁止派生。
- 保存：每次保存生成新版本；后端执行敏感信息扫描和 4 KiB 限制，前端展示失败原因，不吞掉接口错误。

## 4. 生命周期与质量

- 「发布启用」将草稿变为 enabled；「停用」「归档」保留历史版本但不进入新 Run；「删除」只对未被快照/Finding 引用的规则开放。已归档筛选仍能查到归档规则。
- 版本区显示版本号、变更说明、作者和时间。回滚接口创建新的当前版本，前台不覆盖历史版本。
- 质量区展示复现率、误报率和修复率；Finding 去重依据规则、位置和失败签名，统计由后端计算。

## 5. 安全与可访问性

- 规则正文、JSON 配置和质量数据都按不可信用户输入处理；页面不把规则内容拼接到 HTML。
- 所有按钮提供禁用态，保存期间避免重复提交；删除必须二次确认。
- 列表行、筛选控件、编辑字段均有可访问名称；状态通过 `role=status` 告知保存结果，错误通过 `role=alert` 告知。
- 规则不能改变 `authorized_actions`、`allowed_files` 或网络白名单；这些边界由运行时策略独立校验。

## 6. 本次实现与后续

已实现 React/TypeScript 规则页面、`backend/packages/console-service` 数据服务、Node HTTP 路由和 Python Agent 的规则执行。首次控制台启动就显示 5 条内置规则，无需启动 Agent。规则 ID 在首次保存前可完整输入，保存后锁定；切换项目重置编辑器；保存及状态变更后同步刷新版本和提示词预览。

规则由运行时在每次模型请求前按当前阶段、URL、文件范围动态筛选并完整注入；模型没有忽略规则或自行判断适用性的权限。原生工具更新观测后，下次请求替换旧的规则区块。规则详情的预览用于展示单条规则内容；实际 Run 的注入集合由运行时决定并写入 `rules.injected` 事件。

Agent 范围内继续验收规则快照、实际注入、Finding 来源与修复验证；YAML 编辑器、试运行页面、标注和管理界面按平台需要实现，不列为本组件缺口。
