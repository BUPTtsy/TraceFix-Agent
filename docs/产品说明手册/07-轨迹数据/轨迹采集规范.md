# 轨迹采集规范

采集 Agent 工作全过程的审计轨迹；模型返回 `reasoning_content` 时一并保存，作为后续 SFT / RL 数据生产的候选来源。当前主目标为 DeepSeek 类 Chat Completions API；统一训练轨迹格式和导出流水线仍属 📐规划。

## 1. 现状

### 1.1 已采集的内容

| 内容 | 实现 | 证据 |
|---|---|---|
| 每次模型调用的请求 / 响应 / 错误 | 经敏感字段脱敏后分别保存 artifact，发出 `model.request.persisted` / `model.response.persisted` / `model.error.persisted`；记录 `logical_exchange_id`、`schema`、`tool_round`、`attempt` | `backend/packages/agent/src/tracefix/runtime/engine.py:266` |
| 模型 reasoning | 提供时保存在受 scope/run 隔离保护的 response artifact；事件中的 `reasoning_content_present` 只是索引标志，不替代原文。native 下一次请求保留对应 assistant 消息的该字段 | `backend/packages/agent/src/tracefix/runtime/engine.py:287`、`backend/packages/agent/src/tracefix/model/gateway.py:433` |
| token 用量 | 每次实际响应的 `model.usage`；当前不按环境变量单价估算美元费用，`cost_is_configured_estimate: false` | `backend/packages/agent/src/tracefix/runtime/engine.py:328` |
| 决策摘要 | `model.decision`：`Decision.summary`（≤1200 字）、`expected_observation`、证据引用 | `contracts.py:158-162` |
| 工具调用 | `tool.started / tool.completed / tool.error`，包含 intent 与 receipt | `storage/store.py:54,61`、`engine.py:117-136` |
| native 工具协议及回执 | 请求保存 `tools`，响应保存 `tool_calls`；按原始 `tool_call_id` 回传 `role=tool`，工具结果独立保存 artifact 并发出 `model.tool.result.persisted`，关联逻辑调用与轮次 | `backend/packages/agent/src/tracefix/runtime/engine.py:338`、`backend/packages/agent/src/tracefix/model/gateway.py:459` |
| 观测 | a11y 快照 + PNG 截图 + console + network，统一存为 artifact | `engine.py:229-236`、`execution/browser.py:322-334` |
| 补丁 | `.diff` artifact + `patch.applied` 事件 | `engine.py:541-542` |
| 验证 | 六类 `Validation` 记录，均与 `patch_hash / source_manifest / environment_digest` 绑定 | `engine.py:571-578` |
| 知识选择 | `knowledge.selected`：检索词 + 选中文档 | `knowledge/selection.py:48-50` |
| 用户输入 | `interrupt.prompt`、`input.applied` 事件 | `cli/main.py:423`、`engine.py:337` |
| 完整导出 | FINALIZE 阶段输出完整事件 JSON + 中文可读日志 | `engine.py:673-676` |
| 存储 | Postgres `events(run_id, seq, payload)`；artifact 按 scope/run 隔离，中文文件名及索引记录 SHA256，读取时验证完整性，也兼容旧哈希文件名 | `storage/schema.sql:9-12`、`backend/packages/agent/src/tracefix/storage/artifacts.py:98` |

默认模型为 `deepseek-chat`，`TRACEFIX_VISION_MODEL` 留空；浏览器快照、截图仍保存为证据，只有显式配置视觉模型才向模型发送图片。`TRACEFIX_TOOL_MODE=native` 使用浏览器 function tools；`json` 是显式启用的旧动作 JSON 兼容模式，不会在 native 失败时自动切换。接口与工具边界见 [工具调用与 Skill](../03-Agent运行时/工具调用与Skill.md)。

同一 native 交互可包含多轮请求，`attempt` 是当前工具轮次中的请求尝试号；不能只按 `attempt` 合并记录。回放协议时须保留 assistant `tool_calls` 与后续 `role=tool` 的配对，以及函数参数 JSON 字符串；动作先经过工具 schema 与 TraceFix 策略校验，再由 MCP 执行。重复 `tool_call_id` 仅能复用相同参数的已有结果，不能代表再次执行。

### 1.2 缺失的内容

| 缺失项 | 原因 / 证据 |
|---|---|
| 独立 reasoning 元数据与细粒度权限 | 已保存供应商提供的 `reasoning_content`，但没有统一的 reasoning 独立引用、token 标签或 `trace:read_reasoning` 权限模型；当前默认 DeepSeek 请求关闭 thinking，不保证返回该字段 |
| 真实成本 | 已记录供应商返回的 token 用量，没有生产可核对的美元账单 |
| step 级标签 | 没有「这一步推动了进展 / 原地打转 / 导致回退」的标注 |
| 上下文结构 | request 的用户文本仍是已拼装的上下文，缺少各区块 token 分配、裁剪原因和结构化 manifest；native 请求另有 `tools` 与消息角色结构 |
| 轨迹 → 训练格式导出器 | 不存在；`training/dataset.py` 期望的 JSONL 字段在运行时没有生产者 |
| 真实数据 | 仓库中没有任何 `.jsonl` 训练数据；CI smoke 的截图是 1×1 占位图，token 固定为 10/10/20（FAKE CI） |

## 2. 目标设计 📐

本节的 `tracefix.trajectory/2`、标签、独立 reasoning artifact、导出器和权限均为规划，不是当前审计格式或已生成的数据集。保留现有 DeepSeek Chat Completions 消息协议，暂不引入多供应商适配路线。

### 2.1 层级结构

```text
Job ─▶ Run ─▶ Step ─┬─ ModelTurn      一次模型调用（含 reasoning）
                    ├─ ToolExecution  一次工具执行
                    ├─ Observation    一次浏览器观测
                    ├─ Guidance       一条用户干预
                    ├─ Compaction     一次上下文压缩
                    └─ SubAgentRun    一次子 Agent 执行（内部结构递归相同）
```

### 2.2 Step 记录规范（`tracefix.trajectory/2`）

```json
{
  "schema": "tracefix.trajectory/2",
  "ids": {"job": "job_…", "run": "run_…", "step": "stp_…", "parent_step": null, "agent": "main"},
```

规范要点：

- **大字段只存引用**：request、response、reasoning、截图、快照都以 SHA256 引用 artifact，沿用现有的完整性校验。
- **可复现**：`state` 中的哈希加上 `request_ref`，可以精确还原当时的输入。
- **归因**：`refs` 记录模型实际引用了哪些规则、分析结果和用户引导，用于统计「注入内容是否有用」。

### 2.3 Reasoning 采集 📐

现有 response artifact 已保留供应商返回的 `reasoning_content`；下表规划统一元数据，不要求每次响应都有 reasoning，也不据此推断模型内部是否进行推理。

| 响应情况 | 采集方式 | `reasoning.source` |
|---|---|---|
| DeepSeek 类响应提供 `reasoning_content` | 从已有 response artifact 提取受限引用；native 多轮请求保留原 assistant 字段 | `provider` |
| 响应没有 `reasoning_content` | 不生成或补写推理过程；缺失 token 数保留为空 | `none` |

策略调整：

- 如未来增加 thinking 开关，须先验证目标 DeepSeek 模型与工具协议的组合；当前没有按阶段自动开启 thinking 的功能。
- 系统策略中的「Do not expose private reasoning」保留：不要求模型把私有推理写入 summary、PR 描述等面向用户的字段；这不妨碍内部审计保存供应商已返回的字段。
- 规划增加独立 reasoning artifact 和 `trace:read_reasoning` 权限；当前保护边界是 scope/run 隔离与敏感字段脱敏。面向用户的摘要不复制推理原文，同一 native 交互的协议续接仍保留供应商返回的 `reasoning_content`，不能把它误写为「永不回传」。

### 2.4 自动标签

| 标签 | 规则 |
|---|---|
| `progress` | EXPLORE：快照发生有意义的变化，且更接近断言目标 → `advanced`；无变化 → `stalled`；触发 `repeated_action` → `looping` |
| `hypothesis_correct` | DIAGNOSE 的假设位置与最终通过验证的补丁位置重合 |
| `patch_outcome` | 补丁对应的验证结果（六类验证逐项记录） |
| `policy_violation` | 被策略拒绝的动作或工具调用 |
| `guidance_followed` | 模型对用户引导的 ack 与后续行为一致（判断规则化，辅以抽检） |
| `human_decision` | 审批通过 / 驳回、PR 是否合并（通过 webhook 延迟回填） |

### 2.5 存储与留存

| 层 | 存储 | 留存期 |
|---|---|---|
| 热数据 | Postgres `trajectory_steps`（JSONB，按 run 建索引）+ 对象存储中的 artifact | 90 天（可配置） |
| 冷数据 | 对象存储 Parquet / JSONL，按 `date/project` 分区 | 按合同约定 |
| 个人模式 | `.tracefix/trajectories/<run>.jsonl` + 本地 artifact | 用户自行管理 |

### 2.6 采集开关与合规

- 项目级配置 `training_authorized`（默认 false）和 `privacy_class`（`public_or_shared` / `private`），语义与 `training/dataset.py:13-14` 保持一致。
- 未授权的项目仍采集审计记录；规划中的导出器须拒绝训练导出。当前只有 `training/dataset.py` 对输入训练样本的授权检查，尚无轨迹导出器。
- 截图脱敏：从现在「只校验标志位」（`dataset.py:15-16`），升级为真实处理：OCR 识别 → 按规则遮盖邮箱、手机号、token 样式文本 → 生成新图并记录 `redaction_version`。

### 2.7 验收标准

1. 一个真实的 repair Run 结束后，按 Step 导出的记录数等于模型调用数 + 工具执行数 + 观测数，且全部通过 schema 校验。
2. 响应提供 `reasoning_content` 时，受限引用可读取；未提供时标记 `none`，仅在供应商返回相应 token 计数时记录数值，不推算或伪造。
3. 从任意 Step 的 `request_ref` 可以重建脱敏后的请求消息及工具配对，不恢复被移除的 API key、Authorization 或 Cookie。
4. 未授权项目执行导出时，返回 `PermissionError`。
