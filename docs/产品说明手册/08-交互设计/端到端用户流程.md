# 平台调用 Agent 的端到端流程

> 定位更新：2026-10-07。交互主体为上层 GUI 检测—修复平台与 TraceFix Agent 接口；Web / CLI 保留为研发入口。下文稳定任务 API 流程按接口型 Beta 计划实现与验收。

## 1. 职责与输入

| 参与方 | 职责 |
|---|---|
| 平台调用方 | 验证用户与任务授权、选择仓库 / 规则、排队、展示结果、审批与应用补丁 |
| TraceFix 接口层 | 校验输入、创建 / 查询 Run、处理幂等与取消、返回结果和产物 |
| Agent 运行时 | 冻结规范、浏览器检测与复现、源码定位、最小修补、独立验证和审计 |

平台提供受审 Profile、源码 revision、可重置测试环境、目标 / TestSpec 和规则版本；敏感凭据使用部署方的引用，不放入任务正文。TraceFix 不存储平台用户账户或组织成员关系。

## 2. 检测流程

1. 平台选择已就绪仓库与运行配置，提交 Test 请求和幂等键。
2. 接口确认仓库可用并冻结源码、规则、目标和测试规范，返回 Run ID。
3. Agent 执行 PREPARE → EXPLORE → REPRODUCE，记录动作、观测、规则覆盖和证据。
4. 平台轮询状态、事件及 Finding；任务结束后读取权威 result。
5. `BUG_CONFIRMED` 表示缺陷已确认；`NO_BUG_FOUND` 只表示充分覆盖的冻结范围无问题。未检查的必检规则不计为通过。

## 3. 指定缺陷修复流程

1. 平台选择来源 Test Run 的 Finding，提交绑定来源、仓库、规则快照和约束的 Repair 请求。
2. TraceFix 检查来源归属并重新复现；不能把别的仓库、Run 或不明来源证据作为当前修复依据。
3. Agent 执行 DIAGNOSE → PATCH → VERIFY，使用当前源码 hash 做局部编辑。
4. 验证原问题、逆向行为、刷新与正常业务，以及 static / unit / build / health。
5. 接口返回 outcome、diff、补丁验证状态和证据；平台审阅后应用补丁或进入自己的发布流程。

`FIX_VERIFIED` 必须绑定当前补丁与有效验证；空 diff、未验证候选或退化补丁不能作为修复成功。历史 B01 自动报告曾被独立业务审查拒绝，该记录继续作为负例保留。

## 4. 中断、取消与干预

| 情况 | Agent / 接口行为 | 平台处理 |
|---|---|---|
| 忙碌或输入未就绪 | 稳定错误，不伪造已创建 Run | 等待就绪或排队后重试 |
| 重复提交 | 幂等键对应同一任务；完整行为待 B4 验收 | 保存键与 Run 关联 |
| HTTP 断连 | 不因连接断开推断成功或失败 | 按已有 Run 查询状态，避免重复建任务 |
| 指定 Run 取消 | 校验归属并幂等取消；按 Run 接口待补齐 | 展示取消状态及已有产物 |
| 无进展 / 过期观察 | 有界恢复或明确终态，保留证据 | 展示失败原因，按支持范围发起新任务 |
| 副作用结果 UNKNOWN | 保留核查要求，不盲目重放 | 核对外部状态后决定后续任务 |
| 改目标 | 现有 L3 Guidance 确认后派生 Run | 显式确认并保留父子来源，旧证据不等于新结论 |

暂停、继续、审批和引导只能采用实际已支持的状态语义，不承诺任意浏览器阶段透明恢复。接口首版不能无期限等待 TTY 或人工点击。

## 5. 结果消费与验收

平台按 Run 的状态、outcome、规则覆盖、Finding、patch、verification、error 和 provenance 组合展示结果。HTTP 2xx、`COMPLETED` 或进程退出码不能单独用作缺陷修复结论。

首版验收包含一个真实有效闭环、退化补丁拒绝、UNKNOWN、有界恢复、幂等 / 取消和 A → B → A 两仓库隔离。既有 CLI 与 Web 仅做必要兼容性回归；通知、PR 评论和评审者身份由上层平台处理。
