# 刷新持久化复现检查点

在 summary 中逐项说明以下检查点在探索证据中是否满足；没有观测支撑的项写"未证实"。

1. 起点：reset 后的首屏满足 executable_preconditions（例如目标复选框为 unchecked）。
2. 交互：计划中包含使目标状态发生变化的那一次交互，locator 与快照名称完全一致。
3. 即时状态：探索观测中，交互之后目标控件的状态已经改变。这一项用来区分"交互本身失败"和"保存或读回失败"。
4. 保存回执：探索观测中有保存请求（network）或提示。没有的话标注"未观测到保存"，不要推断。
5. 读回：交互之后有 navigate 到同一 URL，并且已经记录了刷新后的观测。
6. 差异：刷新后的状态与 TestSpec.assertions 期望不一致，这就是要复现的失败。

区分三种情况，不要猜根因：
- 第 3 项不满足：交互没有生效，问题出在事件或状态更新环节。
- 第 3 项满足、第 6 项满足：刷新后状态丢失，问题出在持久化或读取环节。
- 两项都看不清：页面可能还没就绪。在 summary 写明证据不足，复现很可能不稳定。
