# 前端根因判定表

| 症状 | 要区分的假设 | 区分证据 |
|---|---|---|
| 操作后界面不变 | handler 未绑定或被阻止；状态未更新；渲染读了别的字段 | 事件绑定行；setter 入参；渲染表达式读取的 key |
| 立即正确、刷新丢失 | 未写入；写入键或形状错；读回被默认值覆盖；hydration 前被初始值写回 | 写请求或 storage 写调用；读回响应；初始化与 effect 的先后 |
| 快速或连续操作才错 | 异步竞态；闭包旧值；重复提交 | 响应应用顺序；是否函数式更新；去重或取消逻辑 |
| 列表只有某几项错 | key 不稳定；id 比较类型不一致 | key 表达式；=== 两侧类型 |
| 空、加载、错误态显示错 | 分支顺序错；loading 未复位；错误被吞 | 分支条件；finally 与复位路径；catch 内容 |
| Vue 数据变了视图不变 | 解构丢失响应性；非响应式字段 | ref/reactive 声明与解构位置 |

## 证据陷阱
- API 正常不能排除前端覆盖；组件重渲染不能证明后端失败。
- 控制台报错可能是噪音，要和症状步骤对应上。
- 测试 mock 与真实请求路径不同，结论要标明来自哪一侧。
